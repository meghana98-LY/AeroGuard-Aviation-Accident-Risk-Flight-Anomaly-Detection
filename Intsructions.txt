# 4. DEEP LEARNING IS THE PRIMARY AI COMPONENT

This is extremely important.

**AeroGuard must use Deep Learning as its primary intelligence layer.**

Do NOT make Isolation Forest, Random Forest, XGBoost, or another traditional ML algorithm the main model simply because it is easier.

First inspect the actual dataset.

Determine whether the data contains:

* timestamps
* flight sequences
* aircraft IDs
* flight IDs
* telemetry measurements
* flight phases
* accident/anomaly labels
* temporal dependencies

If meaningful temporal sequences exist, use an appropriate Deep Learning architecture.

Prioritize:

### Option 1 — LSTM

Use when sequential flight telemetry is available.

### Option 2 — GRU

Use when sequence modelling is required but a lighter architecture is appropriate.

### Option 3 — LSTM/GRU Autoencoder

Use for unsupervised or semi-supervised anomaly detection when abnormal examples are limited.

### Option 4 — Other Deep Learning architecture

Use only if justified by the actual dataset.

Do NOT use a complicated architecture simply because it sounds advanced.

# 10. HYBRID SAFETY ENGINE

Deep Learning is the primary intelligence layer, but AeroGuard should also have a secondary rule-based validation layer.

Architecture:

```text
             Flight Telemetry
                    ↓
          ┌─────────┴─────────┐
          ↓                   ↓
    Deep Learning       Rule Engine
          ↓                   ↓
    DL Anomaly Score    Parameter Checks
          └─────────┬─────────┘
                    ↓
             Risk Assessment
                    ↓
                  Alert
```

Rules may check:

* unusual altitude changes
* excessive vertical speed
* abnormal airspeed
* unusual roll
* unusual pitch
* rapid parameter changes
* sensor inconsistency
* missing telemetry
* stale telemetry

Do not invent aviation limits and present them as certified standards.

Make thresholds configurable.
