# Deep Learning Methodology

## Manual Flight-Risk Assessment

The manual form uses a supervised PyTorch multilayer perceptron (MLP) for flight-level risk ranking. A single flight record is tabular rather than a telemetry sequence, so an MLP is the appropriate starting point; an LSTM is not justified by a single form submission.

Numeric model inputs are aircraft age, engine health, runway length, altitude, airspeed, fuel, duration, visibility, temperature, dew point, humidity, precipitation, wind speed, wind gust, crosswind, and air pressure. Aircraft type and turbulence are one-hot encoded; night flight is binary. Flight number, route, airport, and date are captured for context, but are not classifier inputs.

Train from a curated CSV containing one labeled row per flight and `accident_label` (0 or 1). The script requires a unique `flight_id`, sorts chronologically by `flight_date`, splits 70/15/15 into train/validation/test, and fits normalization statistics on training data only. It saves a PyTorch state-dict checkpoint in `.pkl` format and metadata with validation loss/metrics and held-out test loss, ROC-AUC, PR-AUC, precision, recall, F1, and confusion matrix. The risk-analysis API loads this checkpoint. Risk output is an uncalibrated model index, not an accident probability.

The included CSV already contains 30,000 generated synthetic records, exceeding 1,000 samples; no further augmentation was needed. The generator (`backend/training/generate_synthetic_demo.py`) samples phase-shaped altitude and airspeed profiles and assigns labels from an illustrative heuristic with small random noise. The 16 numeric inputs, nine aircraft one-hot fields, four turbulence one-hot fields, and night-flight flag feed an MLP with 30 inputs, hidden layers of 96 and 48 ReLU units (0.08 dropout after the first layer), and one logit output. The current 100-epoch, batch-size-256 run used AdamW (learning rate 0.001, weight decay 0.001) and weighted binary cross-entropy with logits; validation-loss early stopping selected the best checkpoint after 53 epochs. Validation loss was 0.241, accuracy 0.948, ROC-AUC 0.986, PR-AUC 0.943, precision 0.842, recall 0.872, and F1 0.857 at threshold 0.82. Test loss was 0.239; test ROC-AUC 0.986, PR-AUC 0.948, accuracy 0.947, balanced accuracy 0.913, precision 0.861, recall 0.858, F1 0.859, specificity 0.968, false-positive rate 0.032, and false-negative rate 0.142. The chronological split contained 21,000 training, 4,500 validation, and 4,500 test records. These figures measure recovery of the generated heuristic only. They are not evidence about aviation accident risk and must not be used for operations. The generated CSV is ignored by Git; the generator script, model artifact, and metadata are retained. Replace the demo model with a model trained on valid labeled data before interpreting predictions.

## Telemetry Anomaly Demonstration

The separate live telemetry demo currently uses configurable parameter rules. It does not load or run an LSTM autoencoder; the sequence helper in `backend/app/ai/training.py` is preprocessing groundwork only. Do not present its demo output as a trained deep-learning prediction.
